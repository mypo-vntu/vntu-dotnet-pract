    Практична робота №5. Основи ASP.NET Core, EF Core та SQLite: перший CRUD Web API¶

    ⚠️ WIP — матеріал ще в розробці, зміст може змінюватись.

    Модуль: 2 — мікропроєкт, крок 1 з 4 Тип застосунку: ASP.NET Core Web API + EF Core + SQLite Обсяг: 2–3 год аудиторних + СРС

    Це перша робота наскрізного мікропроєкту (ПР №5–8). Домен, обраний тут за таблицею варіантів, використовується без змін у ПР №6, №7 та №8.

    Основний підхід у ПР №5–8 — контролери (Controller-based API), оскільки це найзручніше для початкового засвоєння структури REST-ресурсів. За погодженням з викладачем студент може замість контролерів реалізувати той самий функціонал через Minimal API endpoints (актуальний, дедалі популярніший підхід в індустрії станом на 2026 рік) — вимоги до звіту та критерії оцінювання при цьому не змінюються.

    Мета роботи¶

    Навчитися створювати проєкт ASP.NET Core Web API, підключати EF Core з провайдером SQLite, проєктувати першу модель даних та реалізовувати базовий CRUD-контролер з використанням асинхронного програмування.

    Завдання¶

    • Обрати варіант предметної області за таблицею нижче (домен використовується без зміни у ПР №6–8).
    • Створити проєкт ASP.NET Core Web API (.NET 10, шаблон webapi, з увімкненим OpenAPI: вбудований Microsoft.AspNetCore.OpenApi + Scalar UI — стандартний стек документації API з .NET 9+, Swashbuckle у новому шаблоні більше не використовується).
    • Підключити пакети Microsoft.EntityFrameworkCore.Sqlite та Microsoft.EntityFrameworkCore.Design.
    • Спроєктувати щонайменше 2 пов'язані сутності (клас-модель) свого домену зі зв'язком «один-до-багатьох» (наприклад, Автор — Книга, Категорія — Товар).
    • Реалізувати AppDbContext з DbSet для кожної сутності, налаштувати рядок підключення до файлової бази SQLite у appsettings.json.
    • Створити та застосувати першу міграцію (dotnet ef migrations add InitialCreate, dotnet ef database update), переконатися, що файл .db створюється і містить таблиці.
    • Реалізувати контролер (або мінімальні API endpoints) з повним CRUD (GET all, GET by id, POST, PUT, DELETE) для головної сутності, використовуючи асинхронні методи (async/await, DbContext.SaveChangesAsync тощо).
    • Заповнити базу тестовими даними (Seed-даними) через міграцію або код при старті застосунку.
    • Перевірити роботу всіх ендпоінтів через Scalar UI або Postman.

    Теоретичні відомості (стисло)¶

    Архітектура ASP.NET Core (Program.cs, конвеєр middleware, Dependency Injection), поняття Web API та контролера, ORM та Code-First підхід EF Core, DbContext та DbSet, міграції, зв'язки між сутностями (навігаційні властивості, зовнішні ключі), основи асинхронного програмування (Task, async/await) у контексті звернень до бази даних.

    Порядок виконання¶

    1. Створити проєкт, перевірити запуск та доступність Scalar UI.
    2. Підключити EF Core + SQLite, налаштувати DI для AppDbContext (Program.cs, appsettings.json).
    3. Спроєктувати моделі даних та навігаційні властивості зв'язку 1-до-багатьох.
    4. Створити та застосувати міграцію, перевірити структуру БД (наприклад, через DB Browser for SQLite).
    5. Реалізувати контролер CRUD для головної сутності асинхронно.
    6. Додати seed-дані, протестувати всі операції через Scalar UI.
    7. Закомітити проєкт у Git-репозиторій (створити .gitignore для bin/obj та файлу БД за потреби).

    Вимоги до звіту¶

    Звіт з практичної роботи оформлюється у вигляді документа (PDF/DOCX) та має містити:

    • тему, мету та номер варіанта завдання;
    • короткий опис реалізованого функціоналу;
    • посилання на репозиторій (GitHub/GitLab) з кодом проєкту та історією комітів;
    • знімки екрана (консоль/Scalar/Postman) з демонстрацією роботи програми;
    • структуру моделі даних (сутності та зв'язки) — схемою або текстовим описом;
    • скріншот структури таблиць БД (наприклад, з DB Browser for SQLite) та Scalar UI з переліком ендпоінтів;
    • висновки (2–4 речення) щодо отриманих результатів та труднощів виконання.
