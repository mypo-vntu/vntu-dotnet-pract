    Налаштування робочого середовища¶

    Цей документ — базовий гайд по налаштуванн робочого середовища для роботи над практичними з дисципліни. Пройдіть його один раз на початку, до того як почнете виконувати практичні. Якщо у вас уже встановлено .NET SDK та IDE, можете одразу переходити до виконання робіт.

    Гайд побудований таким чином, щоб по максимуму уникати використання терміналу. Термінал усе ж знадобиться в кількох місцях (наприклад, для встановлення пакетів на Linux); ці місця позначені окремо, а де можливо, поруч наведено альтернативу.

    Що саме потрібно встановити¶

    Компонент Навіщо Коли знадобиться
    .NET 10 SDK компілятор, середовище виконання (встановлюється один раз через інсталятор, далі непомітний для вас) з ПР №1
    Редактор коду / IDE (Visual Studio, Rider або VS Code) написання, запуск і відлагодження коду з ПР №1
    GitHub Desktop (графічний клієнт Git) + акаунт на GitHub збереження історії коду та здача робіт через посилання на репозиторій — без єдиної команди в терміналі з ПР №1
    DB Browser for SQLite перегляд вмісту файлової бази даних .db з ПР №5
    Postman (або вбудований Scalar UI) ручне тестування Web API з ПР №5

    Мінімальні системні вимоги: Windows 10/11 (x64/ARM64), macOS 13+ (Intel або Apple Silicon), або сучасний дистрибутив Linux (Ubuntu 22.04+/Debian/Fedora тощо).

    1. Встановлення .NET 10 SDK¶

    Встановлюємо саме SDK (Software Development Kit), а не Runtime. SDK вже містить Runtime і всі інструменти для розробки. На Windows і macOS встановити його можна як звичайну програму з використанням інсталятора, що має UI, тоді як на Linux доведеться використовувати термінал.

    Windows¶

    1. Відкрийте у браузері https://dotnet.microsoft.com/download/dotnet/10.0 і натисніть кнопку завантаження інсталятора .NET 10 SDK (x64 — для більшості комп'ютерів, ARM64 — для Windows on ARM).
    2. Запустіть завантажений .exe-файл і пройдіть необхідні етапи встановлення з параметрами за замовчуванням.

    macOS¶

    1. Відкрийте https://dotnet.microsoft.com/download/dotnet/10.0 і завантажте офіційний .pkg-інсталятор (оберіть Arm64 — для Mac з процесором Apple Silicon M1/M2/M3/M4, або x64 — для Intel-Mac; якщо не впевнені, який у вас процесор, це видно в → About This Mac).
    2. Двічі клацніть завантажений .pkg-файл і пройдіть стандартний майстер встановлення macOS (Continue → Continue → Install), як для будь-якого іншого застосунку.

    Альтернатива для тих, хто вже користується Homebrew (не обов'язково): brew install --cask dotnet-sdk у Terminal.

    Linux (Ubuntu/Debian/Fedora)¶

    На Linux графічного інсталятора для .NET SDK від Microsoft немає, тому встановлвати потрібно через термінал (це нормальна й звична практика для Linux). Відкрийте застосунок Terminal і виконайте:

    sudo apt update
sudo apt install -y dotnet-sdk-10.0

    Для Fedora — sudo dnf install dotnet-sdk-10.0. Якщо пакет dotnet-sdk-10.0 не знаходиться (застарілі репозиторії дистрибутива), інструкція з додавання офіційного репозиторію Microsoft для вашого дистрибутива є на https://learn.microsoft.com/dotnet/core/install/linux.

    Як перевірити, що SDK встановлено¶

    Найпростіше — не через термінал, а через сам редактор коду: встановіть IDE (розділ 2 нижче), створіть у ньому новий консольний проєкт і натисніть «Запустити». Якщо програма виконалась і у вікні вивелось Hello, World!, SDK встановлено коректно.

    Якщо ж все таки хочеться перевірити SDK окремо до встановлення IDE, то відкрийте термінал (Windows: PowerShell/cmd; macOS/Linux: Terminal) і введіть:

    dotnet --version

    Має вивести версію на кшталт 10.0.1xx.

    Якщо термінал пише «команда не знайдена» / «dotnet is not recognized», перезапустіть термінал повністю (закрити й відкрити заново) або перезавантажте комп'ютер. Якщо не допомогло, див. розділ «Типові проблеми» нижче.

    2. Встановлення редактора коду / IDE¶

    Для .NET розробки існує 3 основних варіанти редактора коду / IDE: Visual Studio, JetBrains Rider, VS Code. Рекомендації щодо кожного з них залежать від операційної системи. Для Windows рекомендується використовувати Visual Studio, тоді як для Linux та MacOS (хоча є на Windows також) JetBrains Rider, так як вони є повноцінними IDE, а не редакторами коду з розширеннями. VS Code — легший та кросплатформний варіант, який підійде для будь-якої ОС, але вимагає трохи більше ручного налаштування, тому рекомендується лише тим, хто з ним вже працював та має досвід ручного налаштування білд та дебаг задач.

    Visual Studio Community 2026 (лише Windows)¶

    1. Завантажте з https://visualstudio.microsoft.com/downloads/ (безкоштовна редакція Community) і запустіть інсталятор.
    2. У переліку Workloads (візуальний список плиток з прапорцями, нічого вводити не потрібно, лише поставити галочки) обов'язково позначте:
    3. .NET desktop development;
    4. ASP.NET and web development.
    5. Натисніть Install і дочекайтесь завершення встановлення (може тривати 20–40 хвилин); перезавантажте комп'ютер, якщо про це попросить інсталятор.
    6. Щоб створити новий проєкт: Файл → New → Project → оберіть шаблон (наприклад, «Console App») → Next → вкажіть назву й папку → Create. Щоб запустити консольний проєкт, краще використовувати Ctrl+F5 («Start Without Debugging»), а не просто F5: інакше вікно консолі одразу закриється після виконання програми, і ви не встигнете побачити результат (детальніше — у розділі «Типові проблеми»).

    JetBrains Rider (Windows / macOS / Linux)¶

    Rider безкоштовний для некомерційного використання (навчання, особисті/навчальні проєкти, open-source), тому можете сміливо його використосувати. Однією із ключових переваг Rider тут є те, що він своїм UI чимось схожий на IntelliJ IDE, який ви використовували на ООП. Етапи встановлення:

    1. Завантажте з https://www.jetbrains.com/rider/download і запустіть інсталятор (або встановіть через JetBrains Toolbox, https://www.jetbrains.com/toolbox-app/, якщо хочете, щоб оновлення відстежувались автоматично одним застосунком).
    2. При першому запуску оберіть ліцензію Non-Commercial (безкоштовно для навчання/особистих проєктів). Це кнопка у вікні входу, реєстрація через звичайний JetBrains-акаунт, без підтвердження студентського статусу.
    3. Якщо потрібна повна академічна ліцензія (наприклад, для проєктів, що виходять за межі некомерційного використання), оформіть її на https://www.jetbrains.com/community/education/ за студентською поштою @vntu.edu.ua.
    4. Щоб створити новий проєкт: на стартовому екрані натисніть New Solution → оберіть шаблон «Console Application» → вкажіть назву й папку → Create. Щоб запустити — натисніть зелену кнопку ▷ (або Shift+F10/F5) вгорі вікна.

    Visual Studio Code + розширення C# Dev Kit (Windows / macOS / Linux)¶

    VS Code — легкий та кросплатформний редактор, але, на відміну від Visual Studio і Rider, він не має вбудованого створення .NET-проєктів «з коробки». Цю функцію додає розширення C# Dev Kit, і перший запуск проєкту тут може зайняти трохи більше часу, у Visual Studio/Rider.

    1. Завантажте VS Code з https://code.visualstudio.com і встановіть його стандартним способом для вашої ОС (звичайний інсталятор).
    2. Відкрийте VS Code → вкладка Extensions (іконка квадратиків зліва, або Ctrl+Shift+X / Cmd+Shift+X) → у полі пошуку введіть «C# Dev Kit» → натисніть Install на розширенні від Microsoft (воно автоматично підтягне базове розширення C#).
    3. Щоб створити новий проєкт без єдиної команди в терміналі: натисніть Ctrl+Shift+P (Cmd+Shift+P на macOS) — відкриється командна панель, введіть «.NET: New Project», оберіть у списку шаблон «Console App», вкажіть папку та назву. VS Code створить проєкт і відкриє його.
    4. Щоб запустити проєкт — відкрийте вкладку Run and Debug (іконка трикутника з жучком зліва) і натисніть зелену кнопку ▷ Run (або клавішу F5); за потреби C# Dev Kit сам запропонує згенерувати конфігурацію запуску, просто підтвердіть.

    3. Git та обліковий запис на GitHub¶

    Git потрібен для збереження історії коду та здачі робіт (у вимогах до звіту кожної ПР — посилання на репозиторій). Рекомендований інструмент — GitHub Desktop: серед графічних клієнтів Git він найпростіший для початківців, повністю графічний застосунок, у якому створення репозиторію, коміти та завантаження коду на GitHub робляться кнопками, без жодної команди. Як альтернативу можна користуватись вбудованою підтримкою Git прямо в IDE (розділ нижче) — обирайте те, що зручніше саме вам.

    Встановлення GitHub Desktop (рекомендовано)¶

    1. Завантажте з https://desktop.github.com і встановіть стандартним інсталятором для вашої ОС.
    2. При першому запуску натисніть Sign in to GitHub.com — це відкриє браузер для входу/реєстрації акаунта; після входу поверніться в застосунок.
    3. У вікні Configure Git застосунок сам запропонує вказати ваше ім'я та email для комітів (заповнюється в текстових полях, це замінює команду git config у терміналі). Введіть дані і натисніть Finish.
    4. Щоб почати новий проєкт: File → New Repository → вкажіть назву та папку → Create Repository; після написання коду зміни з'являться зліва, впишіть короткий опис і натисніть Commit to main, а потім Push origin, і код опиниться на GitHub.

    Створіть акаунт на https://github.com, якщо ще не маєте (крок 2 вище також запропонує реєстрацію). Рекомендується одразу подати заявку на GitHub Student Developer Pack (https://education.github.com/pack) — за студентською поштою дає безкоштовний доступ до приватних репозиторіїв, Copilot та інших інструментів.

    Альтернатива: вбудована підтримка Git прямо в IDE¶

    Visual Studio, Rider і VS Code мають власні вбудовані панелі для роботи з Git (пункт меню Git/Version Control/вкладка Source Control). Коміт і завантаження на GitHub можна робити прямо з тієї ж програми, де ви пишете код, без встановлення GitHub Desktop окремо. Принцип той самий: кнопки «Commit» і «Push» замість команд у терміналі.

    Організація репозиторію: один репозиторій на весь семестр¶

    Створюйте один репозиторій на початку семестру (наприклад, dotnet-labs-<Прізвище>) і здавайте в ньому всі практичні роботи — не створюйте окремий новий репозиторій під кожну ПР. Усередині розкладіть роботи по папках, наприклад:

    dotnet-labs-nikitchuk/
├── 01-csharp-basics/
├── 02-oop-exceptions/
├── 03-generics-delegates-events/
└── ...

    Кожна ПР — окремий проєкт (своя папка з .sln/.csproj) усередині цього самого репозиторію. Для звіту щоразу посилайтесь на той самий репозиторій, за потреби вказуючи конкретну папку чи комміт.

    Чому так зручніше: - Один стабільний URL для здачі всіх робіт замість пошуку/пересилання нового посилання щоразу. - Уся історія комітів за семестр лишається в одному місці — легше показати прогрес і повернутись до попередньої ПР. - Не потрібно повторно проходити налаштування нового репозиторію (remote, .gitignore тощо) перед кожною роботою.

    4. Інструменти для Модуля 2 (ПР №5–8): EF Core, SQLite, Postman (Поки що НЕ ПОТРІБНО, цю секцію фіналізую лише після того, як зроблю ПР 5-8)¶

    Ці інструменти знадобляться, коли дійдете до наскрізного веб-мікропроєкту, встановлювати їх заздалегідь не обов'язково.

    Робота з міграціями EF Core¶

    • У Rider є вбудований інструмент EF Core (вкладка внизу вікна або View → Tool Windows → EF Core) з кнопками «Add Migration» та «Update Database»: міграції створюються і застосовуються кліками, без набору команд.
    • У Visual Studio мігарції зазвичай виконуються через Package Manager Console (Tools → NuGet Package Manager → Package Manager Console — це вбудована панель усередині Visual Studio, а не окремий термінал): команди Add-Migration ІмʼяМіграції та Update-Database вводяться прямо там.
    • Універсальний спосіб (VS Code, або якщо потрібен саме інструмент командного рядка): інструмент dotnet-ef, який встановлюється один раз командою в терміналі: 
      dotnet tool install --global dotnet-ef
      Далі в ПР №5 команди на кшталт dotnet ef migrations add InitialCreate виконуються так само в терміналі. Конкретні кроки описані безпосередньо в самій ПР №5.

    DB Browser for SQLite (перегляд вмісту бази даних)¶

    Безкоштовна GUI-програма для перегляду таблиць у файлі .db, який створює EF Core з провайдером SQLite.

    • Windows/macOS: завантажте інсталятор з https://sqlitebrowser.org/dl/ і встановіть звичайним способом.
    • Linux (Ubuntu/Debian): sudo apt install sqlitebrowser.

    Postman (ручне тестування Web API)¶

    • Завантажте з https://www.postman.com/downloads/ (доступно для Windows, macOS, Linux) — повністю графічний застосунок.
    • Альтернатива без встановлення: вбудований у сам застосунок Scalar UI (https://localhost:<порт>/scalar/v1 після запуску Web API-проєкту). Там теж можна виконувати запити прямо з браузера, без Postman.

    5. Перевірка: перший тестовий проєкт (якщо ще не робили в розділі 2)¶

    Якщо під час встановлення IDE (розділ 2) ви вже створили й запустили тестовий консольний проєкт і побачили Hello, World!, середовище готове, цей розділ можна пропустити.

    Якщо хочете перевірити через термінал (не обов'язково, лише для тих, кому так зручніше):

    dotnet new console -n HelloDotNet
cd HelloDotNet
dotnet run

    Очікуваний результат: Hello, World!.

    6. Типові проблеми та їх вирішення¶

    У Visual Studio консольне вікно одразу закривається після запуску, і не видно результату Це трапляється, якщо запускати проєкт клавішею F5 («Start Debugging»): Visual Studio закриває вікно консолі одразу після завершення програми. Використовуйте Ctrl+F5 («Start Without Debugging»), тоді вікно консолі лишиться відкритим із написом «Press any key to continue…» після виконання. (У Rider і VS Code такої проблеми немає — вивід лишається у вбудованій панелі.)

    IDE не бачить .NET SDK / пише, що SDK не знайдено Перезапустіть IDE повністю (закрити й відкрити заново), а якщо не допомогло, перезавантажте комп'ютер. SDK встановлюється окремо від IDE (розділ 1), тож переконайтесь, що інсталятор SDK справді завершився без помилок.

    «dotnet: команда не знайдена» / «'dotnet' is not recognized» (при перевірці через термінал) Перезапустіть термінал повністю (не просто нову вкладку, а весь застосунок) або перезавантажте комп'ютер, здебільшого цього достатньо. Якщо не допомогло, ймовірно, під час встановлення шлях до dotnet не додався в системну змінну PATH. Простіше за все перевстановити SDK стандартним інсталятором ще раз.

    На macOS з'являється попередження «застосунок із невідомого розробника» Перейдіть у System Settings → Privacy & Security, прокрутіть вниз до повідомлення про заблокований застосунок і натисніть «Open Anyway».

    Кирилиця нормально не відображається в консолі Windows На початку методу Main додайте: 

    Console.OutputEncoding = System.Text.Encoding.UTF8;
    У самій Visual Studio/Rider/VS Code (де вивід зазвичай показується у вбудованій панелі, а не в старому cmd.exe) це здебільшого й не потрібно.

    Нічого не працює, паніка, ВСЕ ПРОПАЛО У такому випадку: Google, ChatGpt, Claude або будь-який інший AI у допомогу. Ну і розклад практичних занять ви знаєте :)
