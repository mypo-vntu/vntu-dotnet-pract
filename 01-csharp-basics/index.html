    Практична робота №1. Базові конструкції C#. Консольний застосунок¶

    Модуль: 1 — огляд та повторення C# Тип застосунку: консольний (.NET, Console App) Обсяг: 2 год аудиторних + СРС

    Мета роботи¶

    Закріпити навички роботи з базовими типами даних, операторами, керуючими конструкціями (розгалуження, цикли), масивами та методами мови C#; навчитися організовувати консольний діалог введення/виведення даних та структурувати найпростіший застосунок у вигляді меню з циклічним виконанням пунктів.

    Загальні завдання (обов'язкові для будь-якого варіанта)¶

    • Створити консольний проєкт (.NET 10, Console App) з назвою виду Lab1_<Прізвище>.
    • Початковий набір даних (студенти, товари, температури тощо) можна заповнити наперед у коді. Але додайте в меню пункт, що змінює дані під час роботи (додавання нового елемента або редагування наявного) — саме там продемонструйте введення з клавіатури з валідацією через TryParse і цикл повторного запиту при некоректному форматі.
    • Для зберігання даних — масив (Array.Resize при додаванні) або List<T> (Add) на вибір.
    • Реалізувати обробку даних за своїм варіантом (деталі — у таблиці варіантів нижче), використавши щонайменше:
    • умовний оператор або switch;
    • цикл (for/while/foreach);
    • одновимірний або двовимірний масив (або еквівалентний List<T>);
    • 2+ власні методи з параметрами та поверненим значенням (не void-методи, що лише друкують).
    • Вивести результати у читабельному вигляді (заголовки, інтерпольовані рядки); табличне вирівнювання (приклад PrintTable нижче) — плюс, але не обов'язкове.
    • Реалізувати меню (цикл + switch) з повторенням дій до вибору «Вихід».
    • Обробити щонайменше один граничний випадок варіанта (порожній масив, ділення на нуль, недопустиме від'ємне значення тощо).

    Теоретичні відомості¶

    Нижче — лише ті засоби C#, які реально знадобляться в цій роботі (докладніше про кожен — за посиланням MS Learn). Не обов'язково читати все підряд, достатньо розділів, що стосуються вашого варіанта.

    Типи даних та змінні¶

    Базові (вбудовані) типи даних C#

    Ключове слово типу в C# — це просто зручний псевдонім (alias) для типу з .NET (наприклад, int — це System.Int32); обидва записи взаємозамінні, але в C#-коді прийнято писати ключове слово.

    Цілочисельні типи (integral) — відрізняються розміром у пам'яті, а отже й діапазоном значень:

    Тип .NET тип Розмір Діапазон / призначення
    sbyte System.SByte 8 біт від −128 до 127
    byte System.Byte 8 біт від 0 до 255 (без знаку)
    short System.Int16 16 біт від −32 768 до 32 767
    ushort System.UInt16 16 біт від 0 до 65 535
    int System.Int32 32 біт приблизно ±2.1 млрд — основний тип для цілих чисел у цій роботі (оцінки, кількість, лічильники)
    uint System.UInt32 32 біт від 0 до ~4.3 млрд (без знаку)
    long System.Int64 64 біт приблизно ±9.2×10¹⁸ — коли int замалий
    ulong System.UInt64 64 біт від 0 до ~1.8×10¹⁹
    nint / nuint System.IntPtr / UIntPtr залежить від платформи розмір під вказівник платформи; на практиці майже ніколи не потрібні у прикладному коді

    Дробові (floating-point) типи — відрізняються точністю:

    Тип .NET тип Точність / суфікс літерала Призначення
    float System.Single ~7 значущих цифр, суфікс f (9.81f) коли важлива економія пам'яті, точність не критична
    double System.Double ~15–17 значущих цифр, без суфікса за замовчуванням основний тип для дробових чисел у цій роботі (ціни, температури, результати обчислень)
    decimal System.Decimal 28–29 значущих цифр, суфікс m (19.99m), найповільніший, зате без похибок округлення грошові розрахунки, де точність критична (у цій роботі не обов'язковий — double достатньо)

    Інші базові типи:

    Тип .NET тип Опис
    bool System.Boolean логічне значення true/false — результат TryParse, умови в if/циклах
    char System.Char один Unicode-символ у одинарних лапках ('A', '+') — знадобиться варіанту 2 при розборі знака операції
    string System.String рядок тексту в подвійних лапках — імена, назви, введений з консолі текст. Технічно не входить до «простих» (simple) значеннєвих типів вище, але вважається базовим і використовується скрізь
    object System.Object базовий тип, від якого походять усі інші типи в C# (включно з int, bool тощо через боксинг); у цій роботі напряму не знадобиться, згадується для повноти 
    int score = 85;
double price = 21.5;
decimal preciseTotal = 199.99m;
string name = "Іваненко";
bool isValid = int.TryParse("42", out int parsed);
char op = '+';

    Важлива відмінність, що стосується цієї роботи: усі типи вище, крім string і object, — типи значень (value types, технічно struct): змінна безпосередньо містить своє значення і при передачі в метод копіюється. string, object і масиви (int[], string[]) — посилальні типи (reference types): змінна містить посилання на дані в пам'яті; саме тому масив, переданий у метод без ref, метод може змінювати «на місці» (елементи), а без ref/out не може замінити його на інший масив (звідси й потреба в ref для Array.Resize у прикладі №4 нижче). При цьому сам string — виняток серед посилальних типів: він незмінний (immutable) — методи на кшталт Trim/Split не змінюють рядок, а повертають новий. learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/built-in-types

    Загальна інформація

    Ключове слово var — неявна типізація: компілятор сам визначає тип змінної з виразу праворуч і підставляє його на етапі компіляції. Це не те саме, що динамічна типізація (як у Python/JS) — тип фіксується назавжди при оголошенні, просто не пишеться явно. Тому обов'язкова умова — ініціалізація в тому ж рядку (var x; без значення не скомпілюється, бо тип нема з чого вивести):

    var count = 5;              // int
var price = 21.5;           // double
var name = "Іваненко";      // string
var students = new List<string>(); // List<string>

    Використовуйте var, коли тип і так очевидний з правої частини (особливо для довгих generic-типів на кшталт Dictionary<string, List<int>>), і явний тип (int, string, ...), коли var шкодить читабельності або тип не очевидний з контексту. В цій роботі обидва варіанти прийнятні — це питання стилю, а не вимога. learn.microsoft.com/dotnet/csharp/programming-guide/classes-and-structs/implicitly-typed-local-variables

    int.TryParse / double.TryParse — безпечне перетворення рядка в число: повертає true/false замість викидання винятку при некоректному вводі. Це основа валідації консольного вводу в цій роботі.

    string userInput = "12x";
if (int.TryParse(userInput, out int value))
    Console.WriteLine($"Отримано число: {value}");
else
    Console.WriteLine("Введено не число.");
    learn.microsoft.com/dotnet/api/system.int32.tryparse

    if/else — базове розгалуження за умовою; гілок else if може бути скільки завгодно:

    int score = 85;
if (score >= 90)
    Console.WriteLine("відмінно");
else if (score >= 75)
    Console.WriteLine("добре");
else if (score >= 60)
    Console.WriteLine("задовільно");
else
    Console.WriteLine("незадовільно");
    learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements

    switch (звичайний оператор) — зручний, коли варіантів багато і кожен порівнюється з конкретним значенням (а не з діапазоном); кожна гілка case завершується break (або return), інакше — помилка компіляції (на відміну від C/C++, «протікання» між гілками за замовчуванням заборонене):

    char op = '+';
switch (op)
{
    case '+':
        Console.WriteLine("Додавання");
        break;
    case '-':
        Console.WriteLine("Віднімання");
        break;
    default:
        Console.WriteLine("Невідома операція");
        break;
}
    learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements#the-switch-statement

    switch expression — компактніший варіант, що одразу повертає значення замість виконання команд у гілках (зручний для методів на кшталт «визначити категорію за балом» — той самий приклад з if/else if вище, але як вираз):

    static string Classify(double score) => score switch
{
    >= 90 => "відмінно",
    >= 75 => "добре",
    >= 60 => "задовільно",
    _ => "незадовільно",
};
    learn.microsoft.com/dotnet/csharp/language-reference/operators/switch-expression

    Цикли for/while/foreach — вибір залежить від того, чи відома кількість ітерацій наперед (for/foreach — так, while — ні):

    foreach (string day in new[] { "Пн", "Вт", "Ср" })
    Console.WriteLine(day);
    learn.microsoft.com/dotnet/csharp/language-reference/statements/iteration-statements

    Масиви (int[], string[]) — базова структура фіксованого розміру для зберігання набору однотипних значень, з доступом по індексу:

    int[] a = [1, 10, 100, 1000];
Console.WriteLine(a[0]); // 1
    learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/arrays

    Методи з параметрами й поверненим значенням — іменований блок коду, що приймає параметри та повертає результат (а не лише друкує в консоль). 

    static double CalculateAverage(int[] values)
{
    if (values.Length == 0)
    {
        return 0;
    }

    return (double)values.Sum() / values.Length;
}
    learn.microsoft.com/dotnet/csharp/programming-guide/classes-and-structs/methods

    ref/out параметри — передача аргументів за посиланням: out повертає додатковий результат (як у TryParse вище), ref дозволяє методу змінити значення наявної змінної виклику (знадобиться для Array.Resize в прикладі №4 нижче):

    static void Increment(ref int number) => number++;
    learn.microsoft.com/dotnet/csharp/language-reference/keywords/ref

    Інтерпольовані рядки та форматування виводу — вбудовування значень у рядок через $"...", зі специфікаторами вирівнювання й формату {значення,ширина:формат} (докладний розбір і приклад таблиці — у розділі «Приклади коду» нижче):

    double price = 21.5;
Console.WriteLine($"{"Хліб",-15}{price,10:F2}");
    learn.microsoft.com/dotnet/standard/base-types/composite-formatting

    string.Split — розбиття рядка на частини за роздільником (знадобиться варіанту 2, щоб розібрати вираз виду 12 + 7 на операнди й знак операції):

    string[] subs = "12 + 7".Split(' ');
// subs: ["12", "+", "7"]
    learn.microsoft.com/dotnet/api/system.string.split

    Array.Resize — зміна розміру вже створеного масиву (створює новий масив потрібної довжини й копіює елементи); знадобиться, щоб додати новий елемент до масиву, заповненого наперед у коді:

    string[] names = { "Іваненко", "Петренко" };
Array.Resize(ref names, names.Length + 1);
names[^1] = "Коваль";
    learn.microsoft.com/dotnet/api/system.array.resize

    List<T> (Add, індексатор) — узагальнена колекція зі змінним розміром, альтернатива масиву без ручного Array.Resize; у циклах і методах використовується практично так само, як масив:

    List<string> names = new() { "Іваненко", "Петренко" };
names.Add("Коваль");
    learn.microsoft.com/dotnet/api/system.collections.generic.list-1

    Math.Round — округлення дробового числа до заданої кількості знаків (альтернатива форматуванню :F2 при виведенні, потрібна варіанту 4):

    double rounded = Math.Round(7.7669, 2); // 7.77
    learn.microsoft.com/dotnet/api/system.math.round

    Random — генератор випадкових чисел; Next(min, max) повертає ціле число в діапазоні [min, max) (потрібен варіанту 6, щоб загадати число):

    Random rnd = new();
int secret = rnd.Next(1, 101); // від 1 до 100 включно
    learn.microsoft.com/dotnet/api/system.random.next

    Console.ReadLine/WriteLine/Write — читання рядка з консолі та виведення тексту (з переходом на новий рядок або без). learn.microsoft.com/dotnet/api/system.console

    Приклади коду (для орієнтиру — не є готовим розв'язком варіанта)¶

    Наведені фрагменти ілюструють технічні прийоми, потрібні для роботи; логіку конкретного варіанта студент розробляє самостійно.

    1. Валідне введення числа через TryParse і цикл повторного запиту¶

    static int ReadInt(string prompt, int min = int.MinValue, int max = int.MaxValue)
{
    while (true)
    {
        Console.Write(prompt);
        string? input = Console.ReadLine();

        if (int.TryParse(input, out int value) && value >= min && value <= max)
        {
            return value;
        }

        Console.WriteLine($"Некоректне значення. Введіть ціле число від {min} до {max}.");
    }
}

    2. Метод із параметрами та поверненим значенням (обробка масиву)¶

    static double CalculateAverage(int[] values)
{
    if (values.Length == 0)
    {
        return 0;
    }

    int sum = 0;
    foreach (int v in values)
    {
        sum += v;
    }

    return (double)sum / values.Length;
}

    Порожній масив тут не помилка, а звичайний випадок — метод просто повертає 0. А для повідомлення «Немає даних» достатньо окремо перевірити scores.Length == 0 на місці виклику, до звернення до CalculateAverage.

    3. Форматований табличний вивід у консоль (необов'язково, приклад гарного оформлення)¶

    static void PrintTable(string[] names, int[] scores)
{
    Console.WriteLine($"{"Студент",-15}{"Бал",5}");
    Console.WriteLine(new string('-', 20));

    for (int i = 0; i < names.Length; i++)
    {
        Console.WriteLine($"{names[i],-15}{scores[i],5}");
    }
}

    Як це працює: синтаксис вирівнювання й форматування в інтерпольованому рядку.

    Усередині фігурних дужок { } в інтерпольованому рядку ($"...") можна вказати не лише саме значення, а й додаткові вказівки через кому та двокрапку:

    { значення , вирівнювання : формат }
    • значення — будь-який вираз C# (змінна, виклик методу, літерал);
    • ,вирівнювання (необов'язково) — ціле число, що задає мінімальну ширину поля в символах:
    • додатне число (наприклад, ,5) — вирівнювання праворуч, поле доповнюється пробілами зліва;
    • від'ємне число (наприклад, ,-15) — вирівнювання ліворуч, поле доповнюється пробілами справа;
    • якщо саме значення довше за вказану ширину — воно просто виводиться повністю, обрізання не відбувається;
    • :формат (необов'язково) — рядок формату для чисел, дат тощо (наприклад, :F2 — два знаки після коми, :N0 — розділювач тисяч без дробової частини, :C — грошовий формат, :P1 — відсоток з одним знаком після коми, :X — шістнадцяткове число).

    Ці два параметри можна поєднувати. Наприклад, {price,10:F2} виведе число price з двома знаками після коми, вирівняне праворуч у полі шириною щонайменше 10 символів. Зручно для колонки з грошовими сумами, де копійки в усіх рядків мають стояти рівно одна під одною.

    Розширений приклад — таблиця з трьома колонками різних типів (текст, ціле число, дробове число з форматом):

    static void PrintReceipt(string[] itemNames, int[] quantities, double[] prices)
{
    Console.WriteLine($"{"Товар",-18}{"К-сть",7}{"Ціна",10}");
    Console.WriteLine(new string('-', 35));

    for (int i = 0; i < itemNames.Length; i++)
    {
        Console.WriteLine($"{itemNames[i],-18}{quantities[i],7}{prices[i],10:F2}");
    }
}

    Результат виконання (умовний приклад — вирівнювання колонок видно завдяки моноширинному шрифту консолі):

    Товар               К-сть      Ціна
-----------------------------------
Хліб                     2      21.50
Молоко                   1      38.90
Цукерки                  3     115.00

    Той самий підхід ({ значення , ±ширина : формат }) працює і поза інтерпольованими рядками — у методі string.Format(...) та в Console.WriteLine("{0,-15}{1,5}", name, score) з нумерованими плейсхолдерами {0}, {1}. Це називається композитним форматуванням (composite formatting) — більш «класичний» спосіб того самого прийому, який часто трапляється в старішому коді C#.

    4. Розширення передзаповненого набору даних — масив або List<T>¶

    Варіант А — звичайний масив (розширення через Array.Resize):

    // Дані вже заповнені наперед — не потрібно вводити 5 студентів щоразу при запуску
string[] names = { "Іваненко", "Петренко", "Сидоренко", "Коваль", "Мельник" };
int[] scores = { 85, 42, 91, 58, 76 };

// А цей метод викликається з пункту меню "Додати студента" —
// саме тут і демонструється введення з клавіатури з валідацією
static void AddStudent(ref string[] names, ref int[] scores)
{
    Console.Write("Прізвище нового студента: ");
    string newName = Console.ReadLine() ?? "";

    int newScore = ReadInt("Оцінка (0-100): ", 0, 100);

    Array.Resize(ref names, names.Length + 1);
    Array.Resize(ref scores, scores.Length + 1);

    names[^1] = newName;
    scores[^1] = newScore;
}

    Варіант Б — List<T> (той самий сценарій, без Array.Resize):

    List<string> names = new() { "Іваненко", "Петренко", "Сидоренко", "Коваль", "Мельник" };
List<int> scores = new() { 85, 42, 91, 58, 76 };

static void AddStudent(List<string> names, List<int> scores)
{
    Console.Write("Прізвище нового студента: ");
    string newName = Console.ReadLine() ?? "";

    int newScore = ReadInt("Оцінка (0-100): ", 0, 100);

    names.Add(newName);
    scores.Add(newScore);
}

    Зауважте: List<T> — це посилальний тип, тому AddStudent змінює список «на місці» й параметр ref тут не потрібен (на відміну від масиву у варіанті А, де без ref метод отримав би лише копію посилання на старий масив і не побачив би результат Array.Resize). В іншому елементи List<T> перебираються в foreach і передаються в методи так само, як масив.

    Обидва варіанти одразу показують роботу програми на «живих» даних (набір не порожній під час запуску), а введення з клавіатури й валідацію демонструють саме на додаванні нового елемента, а не на одноманітному введенні всього набору заново щоразу.

    5. Меню з циклом та switch expression¶

    static void Main()
{
    bool isRunning = true;

    while (isRunning)
    {
        Console.WriteLine("\n=== Меню ===");
        Console.WriteLine("1. Ввести дані");
        Console.WriteLine("2. Виконати обчислення");
        Console.WriteLine("3. Показати результати");
        Console.WriteLine("0. Вихід");

        int choice = ReadInt("Ваш вибір: ", 0, 3);

        isRunning = choice switch
        {
            1 => HandleInput(),
            2 => HandleCalculation(),
            3 => HandleOutput(),
            0 => false,
            _ => true
        };
    }

    Console.WriteLine("Роботу завершено.");
}

    Варіанти завдань¶

    Кожен варіант нижче описаний з конкретними вхідними даними, переліком обов'язкових операцій та очікуваним виглядом виводу, щоб під час виконання не залишалось відкритих запитань щодо обсягу роботи.

    Варіант 1. Обробка масиву оцінок студентів¶

    Вхідні дані: два паралельні масиви однакової довжини (5–10 елементів) — string[] names (ПІБ або прізвище студента) і int[] scores (оцінка від 0 до 100). Дозволяється заповнити ці масиви наперед у коді замість введення з клавіатури щоразу; через меню варто передбачити пункт «Додати студента», що розширює масиви за зразком прикладу коду №4 (Array.Resize) і саме там демонструє введення з валідацією.

    Обов'язкові операції: - обчислити середній бал по всій групі (CalculateAverage, метод з п.2 прикладів коду); - порахувати кількість студентів з оцінкою нижче 60 («незадовільно») та вивести їхні імена; - знайти студента з найвищою та студента з найнижчою оцінкою (окремий метод, що проходить по масиву scores циклом і порівнює значення за тим самим індексом i у names; за однакового максимуму/мінімуму в кількох студентів достатньо вивести першого знайденого); - розподілити студентів за категоріями оцінки — «відмінно» (90+), «добре» (75–89), «задовільно» (60–74), «незадовільно» (<60) — і вивести кількість студентів у кожній категорії, скориставшись if/else або switch expression у методі, що визначає категорію за балом.

    Граничний випадок для обробки: масив з 0 студентів (порожній ввід) — програма повинна вивести повідомлення «Немає даних» замість спроби ділення на нуль при обчисленні середнього.

    Варіант 2. Калькулятор виразів у консолі¶

    Вхідні дані: рядок з простим арифметичним виразом з двома операндами та однією операцією за раз, що вводиться користувачем у форматі число оператор число (наприклад, 12 + 7); підтримка дужок і виразів з кількома операціями не вимагається — це спрощений калькулятор, а не повноцінний парсер.

    Обов'язкові операції: - розбір введеного рядка на операнди та символ операції (string.Split за пробілом); - підтримка щонайменше 4 операцій: +, -, *, /; - перевірка ділення на нуль з відповідним повідомленням без аварійного завершення програми; - накопичення історії обчислень за сеанс (масив або список рядків виду "12 + 7 = 19") з можливістю вивести всю історію окремим пунктом меню.

    Граничний випадок для обробки: ділення на нуль та введення оператора, якого немає в списку підтримуваних (наприклад, % або ^) — вивести повідомлення про непідтримувану операцію.

    Варіант 3. Каса магазину¶

    Вхідні дані: масив товарів (3–8 позицій), кожна позиція — назва (string), ціна за одиницю (double), кількість (int). Дозволяється заповнити список товарів наперед у коді (масиви-константи); через меню варто передбачити пункт «Додати товар до чека», що розширює масиви за зразком прикладу коду №4 (Array.Resize) і демонструє введення з валідацією.

    Обов'язкові операції: - підрахунок повної суми чека (сума ціна × кількість по всіх позиціях); - застосування знижки 10% до чека, якщо сума перевищує задану межу (наприклад, 1000 грн) — межу задати константою на початку програми; - виведення чека («Назва — Кількість — Ціна — Сума» по кожній позиції) з підсумковим рядком «Разом» (з урахуванням знижки, якщо вона застосована, — окремим рядком показати суму знижки); оформлення у вигляді вирівняної таблиці не обов'язкове, але вітається; - пошук і виведення найдорожчої позиції чека (за сумою ціна × кількість, а не лише за ціною за одиницю).

    Граничний випадок для обробки: кількість товару, введена як 0 або від'ємне число — не додавати таку позицію до чека і вивести попередження.

    Варіант 4. Конвертер величин¶

    Вхідні дані: значення для конвертації (double) та вибір напрямку конвертації через пункт меню.

    Обов'язкові операції: - підтримка щонайменше 3 пар одиниць виміру на вибір студента (наприклад: км ↔ милі, кг ↔ фунти, °C ↔ °F) — не валют, оскільки актуальні курси валют змінюються і не можуть бути «зашиті» в код як стала величина; - реалізація кожної конвертації окремим методом з параметром (значення) і поверненим значенням (результат), без дублювання формули в кількох місцях коду; - округлення результату до 2 знаків після коми при виведенні (Math.Round або форматування :F2); - виведення результату у форматі «12.5 км = 7.77 милі» (з явним зазначенням одиниць виміру в обидва боки).

    Граничний випадок для обробки: введення від'ємного значення там, де воно фізично некоректне (наприклад, від'ємна температура за Кельвіном, якщо обрано таку пару, або від'ємна відстань) — вивести попередження, не забороняючи явно коректні від'ємні значення (наприклад, °C може бути від'ємним).

    Варіант 5. Облік температур за тиждень¶

    Вхідні дані: масив з 7 елементів (double) — температура за кожен день тижня (масив назв днів — «Понеділок», «Вівторок» тощо — можна оголосити константою). Дозволяється заповнити температури наперед у коді; введення з клавіатури з валідацією можна продемонструвати окремим пунктом меню — наприклад, зміна температури обраного дня.

    Обов'язкові операції: - обчислення середньої температури за тиждень; - пошук дня з максимальною та мінімальною температурою (з виведенням назви дня, а не лише індексу); - визначення «аномальних» днів — тих, де температура виходить за межі діапазону [середня − 5, середня + 5], з виведенням списку таких днів; - виведення списку «День — Температура» з позначкою (наприклад, зірочкою *) біля аномальних днів; оформлення у вигляді вирівняної таблиці не обов'язкове, але вітається.

    Граничний випадок для обробки: усі 7 температур однакові — середнє дорівнює кожному значенню, аномальних днів немає; програма не повинна помилково позначати жоден день як аномальний.

    Варіант 6. Гра «Вгадай число»¶

    Вхідні дані: відсутні на старті — число для вгадування генерується програмою випадково (Random, діапазон 1–100), гравець вводить свої спроби.

    Обов'язкові операції: - цикл введення спроб із підказкою «більше»/«менше» після кожної невдалої спроби; - підрахунок кількості спроб до вгадування числа за одну гру; - обмеження максимальної кількості спроб (наприклад, 10) — якщо гравець не вгадав за цю кількість, гра завершується повідомленням із показом загаданого числа; - збереження результатів (кількість спроб) кожної зіграної партії за сеанс роботи програми в масиві/списку та виведення статистики (найкращий результат — мінімальна кількість спроб, середня кількість спроб) окремим пунктом меню.

    Граничний випадок для обробки: перша ж спроба гравця виявляється правильною — статистика має коректно зафіксувати результат «1 спроба», а не пропустити цю партію через відсутність невдалих спроб.
