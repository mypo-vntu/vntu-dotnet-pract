# Практична робота №3. Узагальнення, делегати, події та лямбда-вирази

**Модуль:** 1 — огляд та повторення C#
**Тип застосунку:** консольний (.NET, Console App)
**Обсяг:** 2 год аудиторних + СРС

## Мета роботи

Навчитися застосовувати узагальнені (generic) типи та методи, делегати (у т.ч. вбудовані Func/Action/Predicate), лямбда-вирази та механізм подій для побудови гнучкого та повторно використовуваного коду.

## Завдання

- Реалізувати власний узагальнений клас (наприклад, обмежену колекцію, стек, чергу, репозиторій-в-пам'яті) з обмеженнями типу (where) за потреби.
- Реалізувати узагальнений метод, що приймає делегат (Func/Predicate) як параметр для фільтрації/порівняння/трансформації даних.
- Реалізувати сценарій з подіями (event) та власним класом EventArgs: наприклад, сповіщення про зміну стану об'єкта, з підпискою кількох обробників.
- Продемонструвати використання лямбда-виразів та вбудованих делегатів Func<>, Action<>, Predicate<> для заміни звичайних методів у щонайменше 3 місцях коду.
- Порівняти у звіті реалізацію одного й того самого фрагменту логіки «класичним» методом і лямбда-виразом.

## Теоретичні відомості (стисло)

Узагальнені типи та методи, обмеження типів-параметрів (where T : ...), делегати як типобезпечні вказівники на методи, багатоадресні делегати (multicast), вбудовані делегати Func/Action/Predicate, події (event) як обгортка над делегатом, лямбда-вирази та замикання (closures).

## Порядок виконання

1. Спроєктувати та реалізувати узагальнений клас/структуру даних відповідно до варіанта.
2. Додати узагальнені методи з параметрами-делегатами для гнучкої обробки даних.
3. Реалізувати клас-видавця події та клас(и)-підписники з відповідними обробниками.
4. Замінити частину методів на лямбда-вирази, порівняти читабельність та лаконічність коду.
5. Продемонструвати роботу всього сценарію через консольне меню.

## Варіанти завдань

| № | Завдання (структура даних / подієвий сценарій) |
|---|---|
| 1 | Узагальнений стек Stack<T> «з нуля» + подія OnOverflow при перевищенні місткості. |
| 2 | Узагальнена черга з пріоритетом + подія OnItemProcessed. |
| 3 | Узагальнений репозиторій в пам'яті (Add/Remove/Find<Predicate>) + подія OnItemAdded/OnItemRemoved. |
| 4 | Узагальнений «спостерігач за температурою» (генерик-сенсор) + подія OnThresholdExceeded. |
| 5 | Узагальнена бінарна пошукова структура (проста) з делегатом-компаратором + подія OnSearchCompleted. |
| 6 | Система сповіщень інтернет-магазину: подія OnOrderStatusChanged з кількома підписниками (лог, email-заглушка). |
| 7 | Узагальнений кеш (словник з обмеженим розміром, витіснення найстарішого) + подія OnItemEvicted. |
| 8 | Таймер-заглушка (лічильник тіків) з подією OnTick та підписниками, що виконують різні дії. |
| 9 | Узагальнена колекція-«спостережувана» (аналог ObservableCollection) з подіями додавання/видалення. |
| 10 | Черга завдань (Task Queue) з делегатом-обробником та подією OnTaskCompleted/OnTaskFailed. |
| 11 | Узагальнений валідатор об'єктів (список правил-делегатів Func<T,bool>) з подією OnValidationFailed. |
| 12 | Гаманець/рахунок з подією OnBalanceChanged та підписниками (лог операцій, перевірка ліміту). |

## Вимоги до звіту

Звіт з практичної роботи оформлюється у вигляді документа (PDF/DOCX) та має містити:

- тему, мету та номер варіанта завдання;
- короткий опис реалізованого функціоналу;
- посилання на репозиторій (GitHub/GitLab) з кодом проєкту та історією комітів;
- знімки екрана (консоль/Scalar/Postman) з демонстрацією роботи програми;
- короткий порівняльний фрагмент коду «метод vs лямбда-вираз» з поясненням;
- висновки (2–4 речення) щодо отриманих результатів та труднощів виконання.

## Контрольні питання

1. Навіщо потрібні обмеження типу-параметра (where T : ...) в узагальнених класах?
2. Чим подія (event) відрізняється від звичайного публічного делегата-поля?
3. У чому суть замикання (closure) у лямбда-виразі? Наведіть приклад ризику при захопленні змінної циклу.
4. Чим відрізняються делегати Func, Action та Predicate?
5. Які переваги дає використання generics порівняно з типом object для узагальненого коду?
