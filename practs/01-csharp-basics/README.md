# Практична робота №1. Базові конструкції C#. Консольний застосунок

## Мета роботи

Закріпити навички роботи з базовими типами даних, операторами, керуючими конструкціями (розгалуження, цикли), масивами та методами мови C#; навчитися організовувати консольний додаток з введенням/виведенням даних та структурувати найпростіший застосунок у вигляді меню з пунктами.

## Загальні завдання (обов'язкові для будь-якого варіанта)

- Створити консольний проєкт (.NET 10, Console App)..
- Реалізувати меню (цикл + `switch` або `switch expression`) з повторенням дій до вибору «Вихід».
- Реалізувати обробку даних за своїм варіантом (деталі — у розділі «Варіанти завдань» нижче).
- Виводити результати у читабельному вигляді (заголовки, інтерпольовані рядки).
- Обробити щонайменше один граничний випадок варіанта (порожній масив, ділення на нуль, недопустиме від'ємне значення тощо).

### Типи даних та змінні

**Базові (вбудовані) типи даних C#**

Ключове слово типу в C# — це просто зручний псевдонім (`alias`) для типу з .NET (наприклад, `int` — це `System.Int32`); обидва записи взаємозамінні, але в C#-коді прийнято писати ключове слово.

Цілочисельні типи (integral) — відрізняються розміром у пам'яті, а отже й діапазоном значень:

| Тип | .NET тип | Розмір | Діапазон / призначення |
|---|---|---|---|
| `sbyte` | `System.SByte` | 8 біт | від −128 до 127 |
| `byte` | `System.Byte` | 8 біт | від 0 до 255 (без знаку) |
| `short` | `System.Int16` | 16 біт | від −32 768 до 32 767 |
| `ushort` | `System.UInt16` | 16 біт | від 0 до 65 535 |
| `int` | `System.Int32` | 32 біт | приблизно ±2.1 млрд — **основний тип для цілих чисел** у цій роботі (оцінки, кількість, лічильники) |
| `uint` | `System.UInt32` | 32 біт | від 0 до ~4.3 млрд (без знаку) |
| `long` | `System.Int64` | 64 біт | приблизно ±9.2×10¹⁸ — коли `int` замалий |
| `ulong` | `System.UInt64` | 64 біт | від 0 до ~1.8×10¹⁹ |
| `nint` / `nuint` | `System.IntPtr` / `UIntPtr` | залежить від платформи | розмір під вказівник платформи; на практиці майже ніколи не потрібні у прикладному коді |

Дробові (floating-point) типи — відрізняються точністю:

| Тип | .NET тип | Точність / суфікс літерала | Призначення |
|---|---|---|---|
| `float` | `System.Single` | ~7 значущих цифр, суфікс `f` (`9.81f`) | коли важлива економія пам'яті, точність не критична |
| `double` | `System.Double` | ~15–17 значущих цифр, без суфікса за замовчуванням | **основний тип для дробових чисел** у цій роботі (ціни, температури, результати обчислень) |
| `decimal` | `System.Decimal` | 28–29 значущих цифр, суфікс `m` (`19.99m`), найповільніший, зате без похибок округлення | грошові розрахунки, де точність критична (у цій роботі не обов'язковий — `double` достатньо) |

Інші базові типи:

| Тип | .NET тип | Опис |
|---|---|---|
| `bool` | `System.Boolean` | логічне значення `true`/`false` — результат `TryParse`, умови в `if`/циклах |
| `char` | `System.Char` | один Unicode-символ у одинарних лапках (`'A'`, `'+'`) — знадобиться варіанту 2 при розборі знака операції |
| `string` | `System.String` | рядок тексту в подвійних лапках — імена, назви, введений з консолі текст. Технічно не входить до «простих» (simple) значеннєвих типів вище, але вважається базовим і використовується скрізь |
| `object` | `System.Object` | базовий тип, від якого походять усі інші типи в C# (включно з `int`, `bool` тощо через *боксинг*); у цій роботі напряму не знадобиться, згадується для повноти |

```csharp
int score = 85;
double price = 21.5;
decimal preciseTotal = 199.99m;
string name = "Іваненко";
bool isValid = int.TryParse("42", out int parsed);
char op = '+';
```

Важлива відмінність, що стосується цієї роботи: усі типи вище, крім `string` і `object`, — **значенні типи** (value types, технічно `struct`): змінна безпосередньо містить своє значення і при передачі в метод копіюється. `string`, `object` і масиви (`int[]`, `string[]`) — **посилальні типи** (reference types): змінна містить посилання на дані в пам'яті; саме тому масив, переданий у метод без `ref`, метод може змінювати «на місці» (елементи), а без `ref`/`out` не може замінити його на *інший* масив (звідси й потреба в `ref` для `Array.Resize` у прикладі №3 нижче). При цьому сам `string` — виняток серед посилальних типів: він *незмінний* (immutable) — методи на кшталт `Trim`/`Split` не змінюють рядок, а повертають новий.
[learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/built-in-types](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/built-in-types)

**Загальна інформація**

**Ключове слово `var`** — неявна типізація: компілятор сам визначає тип змінної з виразу праворуч і підставляє його на етапі компіляції. Це **не** те саме, що динамічна типізація (як у Python/JS) — тип фіксується назавжди при оголошенні, просто не пишеться явно. Тому обов'язкова умова — ініціалізація в тому ж рядку (`var x;` без значення не скомпілюється, бо тип нема з чого вивести):

```csharp
var count = 5;              // int
var price = 21.5;           // double
var name = "Іваненко";      // string
var students = new List<string>(); // List<string>
```

Використовуйте `var`, коли тип і так очевидний з правої частини (особливо для довгих generic-типів на кшталт `Dictionary<string, List<int>>`), і явний тип (`int`, `string`, ...), коли `var` шкодить читабельності або тип не очевидний з контексту. В цій роботі обидва варіанти прийнятні — це питання стилю, а не вимога.
[learn.microsoft.com/dotnet/csharp/programming-guide/classes-and-structs/implicitly-typed-local-variables](https://learn.microsoft.com/dotnet/csharp/programming-guide/classes-and-structs/implicitly-typed-local-variables)

**`int.TryParse` / `double.TryParse`** — безпечне перетворення рядка в число: повертає `true`/`false` замість викидання винятку при некоректному вводі. Це основа валідації консольного вводу в цій роботі.

```csharp
string userInput = "12x";
if (int.TryParse(userInput, out int value))
    Console.WriteLine($"Отримано число: {value}");
else
    Console.WriteLine("Введено не число.");
```
[learn.microsoft.com/dotnet/api/system.int32.tryparse](https://learn.microsoft.com/dotnet/api/system.int32.tryparse)

**`if`/`else`** — базове розгалуження за умовою; гілок `else if` може бути скільки завгодно:

```csharp
int score = 85;
if (score >= 90)
    Console.WriteLine("відмінно");
else if (score >= 75)
    Console.WriteLine("добре");
else if (score >= 60)
    Console.WriteLine("задовільно");
else
    Console.WriteLine("незадовільно");
```
[learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements](https://learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements)

**`switch` (звичайний оператор)** — зручний, коли варіантів багато і кожен порівнюється з конкретним значенням (а не з діапазоном); кожна гілка `case` завершується `break` (або `return`), інакше — помилка компіляції (на відміну від C/C++, «протікання» між гілками за замовчуванням заборонене):

```csharp
char op = '+';
switch (op)
{
    case '+':
        Console.WriteLine("Додавання");
        break;
    case '-':
        Console.WriteLine("Віднімання");
        break;
    default:
        Console.WriteLine("Невідома операція");
        break;
}
```
[learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements#the-switch-statement](https://learn.microsoft.com/dotnet/csharp/language-reference/statements/selection-statements#the-switch-statement)

**`switch` expression** — компактніший варіант, що одразу *повертає значення* замість виконання команд у гілках (зручний для методів на кшталт «визначити категорію за балом» — той самий приклад з `if`/`else if` вище, але як вираз):

```csharp
static string Classify(double score) => score switch
{
    >= 90 => "відмінно",
    >= 75 => "добре",
    >= 60 => "задовільно",
    _ => "незадовільно",
};
```
[learn.microsoft.com/dotnet/csharp/language-reference/operators/switch-expression](https://learn.microsoft.com/dotnet/csharp/language-reference/operators/switch-expression)

## Приклади коду (для орієнтиру — не є готовим розв'язком варіанта)

Наведені фрагменти ілюструють технічні прийоми, потрібні для роботи; логіку конкретного варіанта студент розробляє самостійно.

### 1. Валідне введення числа через `TryParse` і цикл повторного запиту

```csharp
static int ReadInt(string prompt, int min = int.MinValue, int max = int.MaxValue)
{
    while (true)
    {
        Console.Write(prompt);
        string? input = Console.ReadLine();

        if (int.TryParse(input, out int value) && value >= min && value <= max)
        {
            return value;
        }

        Console.WriteLine($"Некоректне значення. Введіть ціле число від {min} до {max}.");
    }
}
```

### 2. Метод із параметрами та поверненим значенням (обробка масиву)

```csharp
static double CalculateAverage(int[] values)
{
    if (values.Length == 0)
    {
        return 0;
    }

    int sum = 0;
    foreach (int v in values)
    {
        sum += v;
    }

    return (double)sum / values.Length;
}
```

Порожній масив тут не помилка, а звичайний випадок — метод просто повертає 0. А для повідомлення «Немає даних» достатньо окремо перевірити `numbers.Length == 0` на місці виклику, до звернення до `CalculateAverage`.

### 3. Розширення передзаповненого набору даних — масив або `List<T>`

**Варіант А — звичайний масив** (розширення через `Array.Resize`):

```csharp
// Дані вже заповнені наперед — не потрібно вводити 7 чисел щоразу при запуску
int[] numbers = { 12, 45, -3, 78, 21, 5, 60 };

// А цей метод викликається з пункту меню "Додати число" —
// саме тут і демонструється введення з клавіатури з валідацією
static void AddNumber(ref int[] numbers)
{
    int newNumber = ReadInt("Нове число: ");

    Array.Resize(ref numbers, numbers.Length + 1);
    numbers[^1] = newNumber;
}
```

**Варіант Б — `List<T>`** (той самий сценарій, без `Array.Resize`):

```csharp
List<int> numbers = new() { 12, 45, -3, 78, 21, 5, 60 };

static void AddNumber(List<int> numbers)
{
    int newNumber = ReadInt("Нове число: ");
    numbers.Add(newNumber);
}
```

Зауважте, що `List<T>` — це посилальний тип, тому `AddNumber` змінює список «на місці» й параметр `ref` тут не потрібен (на відміну від масиву у варіанті А, де без `ref` метод отримав би лише копію посилання на *старий* масив і не побачив би результат `Array.Resize`). В іншому елементи `List<T>` перебираються в `foreach` і передаються в методи так само, як масив.

### 4. Меню з циклом та `switch expression`

```csharp
static void Main()
{
    bool isRunning = true;

    while (isRunning)
    {
        Console.WriteLine("\n=== Меню ===");
        Console.WriteLine("1. Ввести дані");
        Console.WriteLine("2. Виконати обчислення");
        Console.WriteLine("3. Показати результати");
        Console.WriteLine("0. Вихід");

        int choice = ReadInt("Ваш вибір: ", 0, 3);

        isRunning = choice switch
        {
            1 => HandleInput(),
            2 => HandleCalculation(),
            3 => HandleOutput(),
            0 => false,
            _ => true
        };
    }

    Console.WriteLine("Роботу завершено.");
}
```

### 5. Повний скелет програми — як усе з'єднати разом

Попередні приклади показували окремі прийоми; тут вони зібрані в один робочий (компільований) файл `Program.cs`, щоб було видно, як частини стикуються між собою. Дані та обробка тут навмисно нейтральні (підрахунок додатних чисел) — це **не** розв'язок жодного варіанта, а лише каркас, який треба наповнити логікою свого варіанта. Даний приклад також демонструє код написаний без використання top-level statements, тому рекомендовано не включати цю опцію при створенні проєкту.

```csharp
class Program
{
    static void Main()
    {
        // === 1. Дані програми (локальна змінна Main, передається в методи через параметри) ===
        // Заповнені наперед у коді — не потрібно вводити елементи щоразу при запуску.
        int[] numbers = { 12, -5, 8, -1, 0, 7 };

        // === 2. Головний цикл меню ===
        bool isRunning = true;

        while (isRunning)
        {
            Console.WriteLine("\n=== Меню ===");
            Console.WriteLine("0. Вихід");
            Console.WriteLine("1. Додати число");
            Console.WriteLine("2. Показати масив");
            Console.WriteLine("3. Показати кількість додатних чисел");

            int choice = ReadInt("Ваш вибір: ", 0, 3);

            // switch expression одразу повертає значення для isRunning —
            // не треба окремо писати isRunning = false; у гілці "0"
            isRunning = choice switch
            {
                1 => HandleAdd(ref numbers),
                2 => HandleShow(numbers),
                3 => HandleShowPositiveCount(numbers),
                0 => false,
                _ => true // сюди потрапити неможливо: ReadInt уже обмежив ввід діапазоном 0-3
            };
        }

        Console.WriteLine("Роботу завершено.");
    }

    // === 3. Методи для кожного пункту меню ===
    // Кожен викликає "робочий" метод з розділу 4 і повертає true, щоб цикл тривав.
    // Масив передається параметром (за посиланням через ref — див. AddNumber), а не полем класу.

    static bool HandleAdd(ref int[] numbers)
    {
        // Саме тут демонструється введення з клавіатури з валідацією (TryParse) —
        // AddNumber всередині викликає ReadInt, тому невалідний ввід сам перезапитається.
        AddNumber(ref numbers);
        return true;
    }

    static bool HandleShow(int[] numbers)
    {
        if (numbers.Length == 0)
        {
            Console.WriteLine("Немає даних.");
            return true;
        }

        Console.WriteLine(string.Join(", ", numbers));
        return true;
    }

    static bool HandleShowPositiveCount(int[] numbers)
    {
        int count = CountPositive(numbers);
        Console.WriteLine($"Додатних чисел: {count}");
        return true;
    }

    // === 4. "Робочі" методи — саме вони мають параметри й повернене значення ===
    // (у своєму варіанті тут буде CalculateAverage/FindMax/Classify тощо, а не CountPositive)

    static int CountPositive(int[] values)
    {
        int count = 0;

        foreach (int v in values)
        {
            if (v > 0)
            {
                count++;
            }
        }

        return count;
    }

    static void AddNumber(ref int[] values)
    {
        int newNumber = ReadInt("Нове число: ");
        Array.Resize(ref values, values.Length + 1);
        values[^1] = newNumber;
    }

    static int ReadInt(string prompt, int min = int.MinValue, int max = int.MaxValue)
    {
        while (true)
        {
            Console.Write(prompt);
            string? input = Console.ReadLine();

            if (int.TryParse(input, out int value) && value >= min && value <= max)
            {
                return value;
            }

            Console.WriteLine($"Некоректне значення. Введіть ціле число від {min} до {max}.");
        }
    }
}
```

Зверніть увагу на структуру: `Main` (розділи 1–2) лише координує — читає вибір і викликає методи; уся логіка обробки (розділ 4) винесена окремо, приймає параметри й повертає результат. У даному прикладі масив `numbers` не зберігається в полі класу — він живе в `Main` і передається в кожен метод параметром (де потрібно змінити сам масив — через `ref`, як у `HandleAdd`/`AddNumber`), проте такий масив можна об'явити статично в класі Program.

### Варіант 2. Калькулятор виразів у консолі

**Дані:** відсутні на старті. Історія обчислень (масив або `List<string>`) спочатку порожня й наповнюється під час роботи програми.

**Мінімальне меню:**

0. Вихід.
1. Обчислити вираз — ввести рядок `число оператор число` (наприклад, `12 + 7`). Підтримуються щонайменше оператори `+`, `-`, `*`, `/`. Успішний результат виводиться та додається до історії у вигляді рядка `"12 + 7 = 19"`. Оператори **не є пунктами меню** — програма визначає їх із введеного рядка.
2. Показати історію обчислень за сеанс.

Підтримка дужок і виразів з кількома операціями **не вимагається** — це спрощений калькулятор, а не повноцінний парсер.

**Рекомендації щодо реалізації:**

- рядок зручно розбирати через `string.Split` за пробілом; варто перевірити, що вийшло рівно три частини й обидва операнди проходять `double.TryParse`, інакше — повідомлення та повернення в меню (або повторний запит);
- розбір і саме обчислення краще винести в окремі методи; метод обчислення приймає операнди й оператор, повертає результат і вибирає дію за оператором через `switch`;
- гарна ідея — одразу після обчислення вивести результат окремим рядком, а не лише додати його в історію;
- за бажанням можна дозволити операнди з десятковою комою/крапкою в довільній кількості пробілів навколо оператора (наприклад, `12+7` без пробілів).

**Граничний випадок для обробки:** ділення на нуль (повідомлення без аварійного завершення програми) та оператор, якого немає в списку підтримуваних (наприклад, `%` або `^`) — повідомлення про непідтримувану операцію.

### Варіант 3. Конвертер величин

**Дані:** відсутні на старті. Значення для конвертації (`double`) вводиться користувачем після вибору напрямку.

**Мінімальне меню:** шість напрямків конвертації (три пари одиниць, кожна — в обидва боки) та «Вихід». Набір фіксований, однаковий для всіх:

0. Вихід.
1. км → милі: `милі = км / 1.609344`
2. милі → км: `км = милі × 1.609344`
3. кг → фунти: `фунти = кг / 0.45359237`
4. фунти → кг: `кг = фунти × 0.45359237`
5. °C → °F: `°F = °C × 9 / 5 + 32`
6. °F → °C: `°C = (°F − 32) × 5 / 9`

Після вибору напрямку програма запитує значення (введення з валідацією `TryParse`) і виводить результат у форматі «12.5 км = 7.77 милі» (з одиницями виміру в обидва боки).

**Рекомендації щодо реалізації:**

- кожну конвертацію варто оформити окремим методом з параметром (значення) і поверненим значенням (результат), без дублювання формули в кількох місцях коду;
- результат зручно округлювати до 2 знаків після коми при виведенні (`Math.Round` або форматування `:F2`);
- якщо в прямому й зворотному напрямку одна пара використовує ту саму константу (наприклад, `1.609344`), винесіть її в окрему іменовану константу — так формула в обох методах виглядає однаково;

**Граничний випадок для обробки:** значення, яке фізично неможливе для обраної величини. При цьому вивести попередження і не виконувати конвертацію. Наприклад: відстань і маса не можуть бути від'ємними; температура може бути від'ємною (наприклад, −10 °C — коректне значення), але не нижчою за абсолютний нуль: −273.15 °C або −459.67 °F.

### Варіант 4. Гра «Вгадай число»

**Дані:** відсутні на старті. Число для вгадування генерується програмою випадково (`Random`, діапазон 1–1000); результати партій за сеанс зберігаються в масиві/списку, який спочатку порожній.

**Мінімальне меню:**

0. Вихід.
1. Нова гра — визначається випадкове число (не показувати гравцю); гравець вводить спроби (введення з валідацією); після кожної невдалої спроби програма підказує чи загадане число є «більше» або «менше». Кількість спроб обмежена (наприклад, 10): якщо гравець не вгадав за цю кількість, гра завершується повідомленням із показом загаданого числа. Результат партії (кількість спроб) зберігається.
2. Показати статистику за сеанс: найкращий результат (мінімальна кількість спроб) та середня кількість спроб.

**Рекомендації щодо реалізації:**

- одну партію варто винести в окремий метод, що приймає максимальну кількість спроб і повертає кількість використаних спроб;
- підрахунок статистики зручно оформити окремими методами (мінімум, середнє) по збережених результатах;
- максимальну кількість спроб краще задати константою на початку програми, а не «зашивати» число в кілька місць коду;
- гарна ідея — після кожної невдалої спроби виводити, скільки спроб залишилось, а не лише підказку «більше»/«менше»;

**Граничний випадок для обробки:** перша ж спроба гравця виявляється правильною — статистика має коректно зафіксувати результат «1 спроба», а не пропустити цю партію через відсутність невдалих спроб.
