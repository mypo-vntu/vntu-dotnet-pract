# Практична робота №7. Автентифікація та авторизація в ASP.NET Core

> ⚠️ **WIP** — матеріал ще в розробці, зміст може змінюватись.

**Модуль:** 2 — мікропроєкт, крок 3 з 4
**Тип застосунку:** розширення проєкту з ПР №5–6 (той самий домен/репозиторій)
**Обсяг:** 2–3 год аудиторних + СРС

> Використовується той самий варіант домену, що й у ПР №5–6 (див. таблицю варіантів у файлі ПР №5).

## Мета роботи

Навчитися реалізовувати автентифікацію користувачів на основі JWT (JSON Web Token) в ASP.NET Core Web API, розмежовувати доступ до ендпоінтів за ролями та політиками авторизації.

## Завдання

- Реалізувати сутність користувача (User) — власну модель або на основі ASP.NET Core Identity — зі зберіганням у тій самій базі SQLite (окрема таблиця/DbContext).
- Реалізувати ендпоінти реєстрації (POST /api/auth/register) та автентифікації (POST /api/auth/login) з хешуванням паролів (не зберігати паролі у відкритому вигляді).
- Реалізувати видачу JWT-токена при успішному логіні (з клеймами: ідентифікатор користувача, роль, термін дії) та підключити middleware перевірки токена (JwtBearer).
- Ввести щонайменше дві ролі (наприклад, Admin і User) та розмежувати доступ до ендпоінтів з ПР №6: операції зміни даних (POST/PUT/DELETE) — лише для Admin (або власника ресурсу), читання — доступне автентифікованим користувачам (за потреби домену).
- Використати атрибути [Authorize]/[Authorize(Roles="...")] та/або політики авторизації (AuthorizationPolicy) для щонайменше одного нетривіального правила доступу.
- Налаштувати Scalar UI (або Swagger UI, якщо використовується сумісний варіант) для підтримки передачі JWT-токена (кнопка Authorize/Auth) для зручного тестування захищених ендпоінтів.
- Продемонструвати та задокументувати сценарії: успішний доступ з валідним токеном, відмову 401 Unauthorized без токена, відмову 403 Forbidden при недостатніх правах.

## Теоретичні відомості (стисло)

Відмінність автентифікації від авторизації, структура JWT (header.payload.signature), клейми (claims), життєвий цикл токена, схема автентифікації JwtBearer у ASP.NET Core, хешування паролів (наприклад, через ASP.NET Core Identity PasswordHasher), атрибутна та політикова авторизація, коди статусу 401 і 403.

## Порядок виконання

1. Реалізувати модель користувача та ендпоінти реєстрації/логіну з хешуванням паролів.
2. Налаштувати генерацію JWT (сервіс видачі токена, параметри Issuer/Audience/Key/термін дії у конфігурації).
3. Підключити middleware автентифікації JwtBearer у Program.cs, перевірити захист довільного ендпоінта [Authorize].
4. Ввести ролі, призначити [Authorize(Roles=...)] або політики до відповідних ендпоінтів з ПР №6.
5. Налаштувати Scalar UI для передачі Bearer-токена.
6. Протестувати всі сценарії доступу (без токена, з токеном без потрібної ролі, з коректним токеном).
