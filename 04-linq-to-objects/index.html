    Практична робота №4. LINQ to Objects: аналіз та обробка колекцій даних¶

    ⚠️ WIP — матеріал ще в розробці, зміст може змінюватись.

    Модуль: 1 — огляд та повторення C# Тип застосунку: консольний (.NET, Console App) Обсяг: 2 год аудиторних + СРС

    Мета роботи¶

    Набути практичних навичок побудови запитів LINQ to Objects (метод-синтаксис та query-синтаксис) для фільтрації, сортування, групування, агрегування та проєктування даних у колекціях об'єктів.

    Загальні завдання (обов'язкові для будь-якого варіанта)¶

    • Створити консольний проєкт (.NET 10, Console App) у Visual Studio / Rider / VS Code з назвою виду Lab4_<Прізвище>.
    • Сформувати колекцію об'єктів (не менше 20–30 записів) відповідно до варіанта завдання. Колекцію дозволяється (і навіть рекомендується) заповнити наперед у коді — масивом ініціалізації, List<T> з колекційним ініціалізатором, або генерацією через цикл зі псевдовипадковими даними (Random) — вводити 20–30 записів вручну з клавіатури для цієї роботи не потрібно.
    • Реалізувати щонайменше 8 різних LINQ-запитів, що охоплюють: Where, OrderBy/OrderByDescending/ThenBy, Select (проєкція в анонімний тип або DTO), GroupBy, агрегатні функції (Count, Sum, Average, Min, Max), Join (з'єднання двох колекцій), Any/All.
    • Реалізувати щонайменше 2 запити у query-синтаксисі (from...where...select) на додаток до методного синтаксису — на тих самих або еквівалентних запитах, щоб порівняння в звіті було змістовним.
    • Реалізувати просте меню, що дозволяє вибрати, який зі звітів/запитів вивести, без перезапуску програми, аж до пункту «Вихід». Одне значення (наприклад, поріг фільтрації чи назва групи для пошуку) варто зробити параметром, який вводиться з клавіатури з валідацією через TryParse, — щоб частина запитів виконувалась за критерієм, заданим користувачем, а не лише за жорстко «зашитим» у код значенням.
    • Вивести результати кожного запиту у консоль у зрозумілому вигляді (наприклад, звіт «топ-5», «статистика за групами»). Табличне вирівнювання виводу не є обов'язковим, але вітається.
    • Реалізувати збереження підсумкового звіту (агрегованих результатів) у текстовий/CSV-файл (File.WriteAllText/File.WriteAllLines).

    Теоретичні відомості (стисло)¶

    Відкладене (deferred) та негайне (immediate) виконання запитів, метод- і query-синтаксис LINQ, стандартні оператори послідовностей, групування та агрегування, з'єднання колекцій (Join, GroupJoin), проєкція в анонімні типи, робота з IEnumerable<T>.

    Довідник: обов'язкові до використання методи та ключові слова¶

    Метод / конструкція Коротко про призначення Посилання (MS Learn)
    Where Фільтрація послідовності за умовою (Predicate-подібним лямбда-виразом) https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.where
    OrderBy / OrderByDescending / ThenBy Сортування за зростанням/спаданням за ключем; ThenBy додає вторинний критерій сортування для елементів з однаковим первинним ключем https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.orderby
    Select Проєкція — перетворення кожного елемента послідовності на новий об'єкт (часто — анонімний тип із потрібними полями) https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.select
    GroupBy Групування елементів за ключем; результат — послідовність груп, кожна з яких сама є послідовністю елементів з однаковим ключем https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.groupby
    Count, Sum, Average, Min, Max Агрегатні функції — обчислюють одне підсумкове значення для всієї послідовності (або для кожної групи після GroupBy) https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.count · https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.average
    Join З'єднання двох послідовностей за спільним ключем (аналог SQL INNER JOIN) — результат містить лише елементи, для яких знайдено відповідність в обох колекціях https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.join
    Any / All Any — чи існує хоча б один елемент, що задовольняє умову; All — чи задовольняють умову геть усі елементи послідовності https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.any · https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.all
    Query-синтаксис (from...where...select) Альтернативний, SQL-подібний спосіб запису того самого запиту — компілятор перетворює його на виклики тих самих методів розширення https://learn.microsoft.com/en-us/dotnet/csharp/linq/get-started/query-syntax-and-method-syntax-in-linq
    Відкладене виконання (deferred execution) Запит LINQ обчислюється не в момент оголошення, а в момент фактичного перебору результату (foreach, ToList() тощо) — важливо розуміти для коректної роботи з даними, що можуть змінитись між оголошенням запиту і його виконанням https://learn.microsoft.com/en-us/dotnet/standard/linq/deferred-execution-lazy-evaluation
    Анонімні типи (new { ... }) Тип без явного оголошення класу, що генерується компілятором «на льоту» — зручно для проєкції в Select, коли потрібні лише кілька полів для виводу https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/types/anonymous-types
    File.WriteAllText / File.WriteAllLines Запис рядка або масиву рядків у текстовий файл одним викликом — знадобиться для збереження підсумкового звіту https://learn.microsoft.com/en-us/dotnet/api/system.io.file.writealllines

    Приклади коду (для орієнтиру — не є готовим розв'язком варіанта)¶

    1. Підготовка колекції даних наперед у коді¶

    public record Student(string Name, string Group, int Score);

List<Student> students = new()
{
    new("Іваненко", "ПЗ-31", 85),
    new("Петренко", "ПЗ-31", 42),
    new("Сидоренко", "ПЗ-32", 91),
    new("Коваль", "ПЗ-32", 58),
    // ... ще щонайменше 16-26 записів — можна дописати вручну
    // або згенерувати циклом із Random для потрібної кількості
};

    2. Фільтрація, сортування та проєкція (метод-синтаксис)¶

    var topStudents = students
    .Where(s => s.Score >= 60)
    .OrderByDescending(s => s.Score)
    .Take(5)
    .Select(s => new { s.Name, s.Score }) // проєкція в анонімний тип
    .ToList();

foreach (var s in topStudents)
{
    Console.WriteLine($"{s.Name} — {s.Score}");
}

    3. Групування та агрегування¶

    var statsByGroup = students
    .GroupBy(s => s.Group)
    .Select(g => new
    {
        Group = g.Key,
        Average = g.Average(s => s.Score),
        Count = g.Count()
    })
    .OrderByDescending(g => g.Average);

foreach (var stat in statsByGroup)
{
    Console.WriteLine($"{stat.Group}: середній бал {stat.Average:F1}, студентів {stat.Count}");
}

    4. Той самий запит у query-синтаксисі¶

    var statsByGroupQuery =
    from s in students
    group s by s.Group into g
    orderby g.Average(x => x.Score) descending
    select new { Group = g.Key, Average = g.Average(x => x.Score), Count = g.Count() };

    5. Join двох пов'язаних колекцій¶

    public record Teacher(string Group, string TeacherName);

List<Teacher> teachers = new()
{
    new("ПЗ-31", "Коваленко О.І."),
    new("ПЗ-32", "Мельник Т.П.")
};

var studentsWithTeachers = students.Join(
    teachers,
    s => s.Group,          // ключ з першої колекції
    t => t.Group,          // ключ з другої колекції
    (s, t) => new { s.Name, s.Group, Curator = t.TeacherName });

    6. Збереження підсумкового звіту у файл¶

    var lines = statsByGroup.Select(s => $"{s.Group};{s.Average:F1};{s.Count}");
File.WriteAllLines("report.csv", new[] { "Group;AverageScore;Count" }.Concat(lines));
Console.WriteLine("Звіт збережено у файл report.csv");

    Порядок виконання¶

    1. Підготувати вихідну колекцію даних (ініціалізація в коді або генерація циклом з Random — див. приклад коду №1).
    2. Побудувати послідовно запити на фільтрацію та сортування (Where, OrderBy).
    3. Побудувати запити з групуванням та агрегуванням (GroupBy + Count/Sum/Average), вивести підсумкову статистику.
    4. Реалізувати щонайменше один Join між двома пов'язаними колекціями.
    5. Переписати щонайменше 2 запити у query-синтаксисі, порівняти з методним варіантом.
    6. Оформити консольне меню та експортувати підсумковий звіт у файл.

    Варіанти завдань¶

    Варіант 1. Студенти та оцінки¶

    Дані (20–30 записів): record Student(string Name, string Group, int Score) — прізвище, назва групи (3–4 різні групи), оцінка (0–100).

    Обов'язкові запити: - середній бал за кожною групою (GroupBy + Average); - топ-5 студентів за оцінкою по всій вибірці (OrderByDescending + Take); - розподіл кількості студентів за діапазонами оцінок («відмінно» 90+, «добре» 75–89, «задовільно» 60–74, «незадовільно» <60) — групування за обчислюваним ключем-діапазоном; - перевірка через All, чи всі студенти заданої групи (вводиться з клавіатури) мають оцінку не нижче заданого порогу (також вводиться з клавіатури).

    Граничний випадок для обробки: група, введена користувачем, якої немає серед даних — запит має повернути порожній результат і зрозуміле повідомлення «Групу не знайдено», а не виняток.

    Варіант 2. Товари та замовлення інтернет-магазину¶

    Дані (20–30 записів): record Product(string Name, string Category, decimal Price) (10–15 товарів у 3–4 категоріях) та record OrderItem(string ProductName, int Quantity) (список позицій замовлень, 15–20 записів, що посилаються на назви товарів).

    Обов'язкові запити: - топ товарів за сумарною кількістю проданих одиниць (GroupBy за назвою товару + Sum кількості); - виручка за категоріями — Join між OrderItem і Product за назвою товару, групування за категорією, сума Price * Quantity; - товари, які жодного разу не замовляли (з використанням Any/All або Except за назвами) — вивести їх список; - топ-3 найдорожчих товари в категорії, введеній користувачем з клавіатури.

    Граничний випадок для обробки: категорія без жодного замовленого товару — виручка за такою категорією має вивестись як 0, а не бути відсутньою в звіті чи спричиняти помилку.

    Варіант 3. Співробітники та відділи¶

    Дані (20–30 записів): record Employee(string Name, string Department, decimal Salary, int YearsOfService) (4–5 відділів).

    Обов'язкові запити: - середня зарплата за кожним відділом, відсортована за спаданням середньої зарплати; - співробітники із стажем більше N років (N вводиться з клавіатури), відсортовані за прізвищем, потім за стажем (OrderBy + ThenBy); - відділ із найбільшою сумарною фактичного фондом заробітної плати (GroupBy + Sum + OrderByDescending + First); - перевірка через Any, чи є у відділі, введеному з клавіатури, хоча б один співробітник із зарплатою вище заданого порогу.

    Граничний випадок для обробки: N (мінімальний стаж), більший за максимальний стаж серед усіх співробітників — запит має повернути порожній список без помилки.

    Варіант 4. Книги бібліотеки та автори¶

    Дані (20–30 записів): record Book(string Title, string Author, string Genre, int Year) (5–6 різних жанрів, 8–10 різних авторів, деякі автори мають кілька книг).

    Обов'язкові запити: - кількість книг за кожним жанром, відсортована за спаданням кількості; - автори з двома й більше книгами в колекції (GroupBy за автором + Where(g => g.Count() >= 2)); - книги, видані після року, введеного з клавіатури, відсортовані за роком видання; - найпопулярніший жанр (з найбільшою кількістю книг) — окремим агрегатним запитом з використанням OrderByDescending(...).First().

    Граничний випадок для обробки: рік, введений користувачем, більший за рік видання найновішої книги в колекції — запит на «книги після цього року» має повернути порожній список без помилки.

    Варіант 5. Транзакції банківських карток¶

    Дані (20–30 записів): record Transaction(string CardHolder, string Category, decimal Amount, DateOnly Date) (5–6 категорій витрат: «Продукти», «Транспорт», «Розваги» тощо, дати в межах одного-двох місяців).

    Обов'язкові запити: - сумарні витрати за кожною категорією, відсортовані за спаданням суми; - топ-5 найбільших окремих транзакцій за сумою; - витрати власника картки, введеного з клавіатури, згруповані за категоріями, з підсумковою сумою по кожній категорії; - перевірка через Any, чи є серед транзакцій хоча б одна, що перевищує поріг «підозріло великої суми» (задається константою або вводиться з клавіатури), з виведенням таких транзакцій.

    Граничний випадок для обробки: власник картки, введений користувачем, без жодної транзакції в даних — запит має коректно повернути «Транзакцій не знайдено», а не порожню помилку при спробі згрупувати порожню послідовність.

    Варіант 6. Автомобілі автосалону¶

    Дані (20–30 записів): record Car(string Brand, string Model, int Year, decimal Price) (6–8 різних марок).

    Обов'язкові запити: - середня ціна автомобіля за кожною маркою, відсортована за спаданням середньої ціни; - автомобілі, випущені пізніше року, введеного з клавіатури, відсортовані за ціною за зростанням; - марка з найбільшою кількістю представлених моделей у колекції (GroupBy за маркою + Count + OrderByDescending); - перевірка через All, чи всі автомобілі заданої марки (вводиться з клавіатури) не перевищують заданого цінового ліміту.

    Граничний випадок для обробки: марка, введена користувачем, якої немає серед даних — запити «середня ціна» та перевірка через All мають коректно обробити цей випадок (наприклад, вивести «Марку не знайдено» замість помилки чи хибного true від All на порожній послідовності — саме тому в звіті варто окремо пояснити, чому All на порожній колекції завжди повертає true, і як це врахувати в повідомленні для користувача).
